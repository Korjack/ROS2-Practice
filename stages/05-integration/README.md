# 5단계 — 통합 (최종 목표)

## 목표

3·4단계에서 학습한 정책을 **ROS2 노드로 감싸** 시뮬레이터 속 로봇을 제어한다.
실제 로봇 시스템에서 AI 모델이 들어가는 방식과 같은 구조.

```
[시뮬레이터] --/joint_states--> [정책 노드] --/joint_commands--> [시뮬레이터]
                                     ^
                              /target_point
```

## 세션 과제

패키지: `ws/src/my_arm_policy`

- [ ] **S1. MuJoCo 시뮬 노드**
  MuJoCo를 ROS2 노드 안에서 돌린다: 타이머마다 `mj_step` → `/joint_states` 발행, `/joint_commands` 구독해서 적용.
  브리지 라이브러리 없이 직접 작성 (구조를 이해하는 게 목적).
- [ ] **S2. 정책 노드**
  학습한 모델(3단계 PPO 또는 4단계 BC)을 불러와서
  `/joint_states` + `/target_point` → 관측 구성 → 추론 → `/joint_commands` 발행.
  **학습 때와 관측 구성 순서·단위가 정확히 같은지** 확인하는 테스트 작성.
- [ ] **S3. 타이밍**
  제어 주기(예: 50Hz)를 정하고, 추론 시간과 실제 주기를 측정해 기록.
  추론이 주기보다 느리면 어떻게 되는지 일부러 지연을 넣어 확인.
- [ ] **S4. Launch와 기록**
  launch 하나로 시뮬 노드 + 정책 노드 + rviz2 실행.
  `ros2 bag record`로 한 번의 실행을 기록하고 재생해서 분석.
- [ ] **S5. Gazebo에 같은 정책 적용 (sim-to-sim)**
  2단계의 Gazebo 팔에 같은 정책 노드를 연결.
  MuJoCo에서보다 성능이 떨어진다면 원인(물리 파라미터, 제어 방식, 주기 차이)을 찾아 기록.
- [ ] **S6. 영상 정책 연결**
  S1 시뮬 노드에서 카메라 영상을 `sensor_msgs/Image`로 발행하고, 4단계 S6의 영상 정책을 정책 노드에 연결.
  영상 토픽의 QoS(1단계 S6), 메시지 크기·전송 지연, 관절 상태와 영상의 시각 맞추기를 확인.
- [ ] **S7. 정리**
  이 저장소 README에 데모 GIF와 "배운 것 / 다음에 해볼 것" 정리.

## 완료 기준

- launch 한 번으로, 학습한 정책이 ROS2를 통해 시뮬레이터 속 팔을 목표점으로 움직인다.
- S5의 성능 차이를 근거와 함께 설명할 수 있다.

## 자가 점검 질문

1. 정책 노드가 "학습 환경"과 달라질 수 있는 지점을 모두 꼽으면?
2. 정책이 학습된 주기와 ROS2 제어 주기가 다르면 무슨 일이 생기나?
3. 시뮬레이터와 정책을 한 프로세스에 넣지 않고 노드로 나누어 얻는 것과 잃는 것은?
4. 실제 로봇이었다면 S5보다 더 큰 차이가 날 부분은?
5. 영상과 관절 상태가 서로 다른 시각에 찍힌 값이라면 정책에 어떤 영향이 있나?
